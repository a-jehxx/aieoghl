# HSM — 집 물건 보관 관리 웹앱

집 안 물건을 어디에 뒀는지 도면과 사진으로 기록해두고, 이름으로 검색해서 위치를 찾는 모바일 웹앱입니다.
React + TypeScript + Vite + Tailwind CSS + zustand로 만들었습니다.

프로젝트 규칙과 데이터 모델은 [`CLAUDE.md`](./CLAUDE.md)를 참고하세요.

## Firebase 설정

이 앱은 Firebase(Realtime Database + 익명 로그인)를 사용합니다. `.env.example`을 복사해 `.env`를 만들고,
Firebase 콘솔의 웹 앱 설정값을 채워 넣으세요.

```bash
cp .env.example .env
```

`.env`가 없거나 값이 비어 있으면 앱은 자동으로 로컬(메모리) 저장을 사용합니다(새로고침하면 데이터가 사라짐).

Firebase 설정 없이도(또는 설정과 별개로) 메인 화면의 "체험하기" 버튼을 누르면 샘플 집으로 모든 기능을 바로 써볼 수 있습니다. 체험 모드는 Firebase를 전혀 읽거나 쓰지 않고, 종료하면 초기 상태로 돌아갑니다.

### 보안 규칙 배포

`database.rules.json`에 Realtime Database 규칙이 있습니다. 그 집의 구성원(members에 내 uid가 있는 사람)만 그 집 데이터를 읽고 쓸 수 있고, 가족 공유 코드(joinCodes)는 정확한 코드로 한 건만 읽을 수 있으며 생성·삭제는 그 집 소유자만 할 수 있습니다.

- Firebase CLI로 배포: `firebase deploy --only database` (사전에 `firebase login`, `firebase use <프로젝트id>` 필요)
- 또는 Firebase 콘솔 → Realtime Database → Rules 탭에 `database.rules.json` 내용을 붙여넣고 게시

규칙 파일이 바뀔 때마다(가족 공유 기능 추가 등) 다시 배포해야 실제로 적용됩니다. 위 명령을 다시 실행하면 됩니다.

## 로컬에서 실행하기

```bash
npm install
npm run dev
```

터미널에 나오는 주소(기본 `http://localhost:5173`)를 브라우저에서 열면 됩니다.

## 같은 와이파이에 있는 휴대폰에서 확인하기

```bash
npm run dev -- --host
```

터미널에 표시되는 `Network` 주소(예: `http://192.168.0.x:5173`)를 휴대폰 Chrome 브라우저 주소창에 입력해서 접속합니다.
접속 후 브라우저 메뉴에서 "홈 화면에 추가"를 하면 앱처럼 사용할 수 있습니다.

## 빌드

```bash
npm run build
npm run preview
```

## Firebase Hosting에 배포하기

폰에서 "홈 화면에 추가"로 진짜 설치하려면 HTTPS 주소가 필요합니다. Firebase Hosting(무료 Spark 요금제)에 배포하세요.

```bash
npm install -g firebase-tools   # 한 번만
firebase login                  # 브라우저에서 Google 계정 로그인
firebase use --add              # 이 프로젝트가 쓸 Firebase 프로젝트 선택
npm run build                   # dist/ 생성
firebase deploy --only hosting,database
```

배포가 끝나면 터미널에 `https://<프로젝트id>.web.app` 형태의 주소가 나옵니다. 이 주소를 폰 Chrome에서 열면 설치 배너(또는 Chrome 메뉴 → 홈 화면에 추가)로 앱처럼 설치할 수 있습니다.
Cloud Functions나 Blaze(종량제) 요금제는 쓰지 않으므로 Spark(무료) 요금제 그대로 배포됩니다.

### 배포 후 점검 목록

- [ ] 배포된 주소를 열면 오류 없이 메인 화면이 뜬다.
- [ ] 새 집을 만들고 도면·가구·보관함 사진을 올린 뒤 새로고침해도 남아 있다.
- [ ] 다른 기기(또는 다른 브라우저 탭)에서 같은 주소를 열면 방금 한 변경이 실시간으로 보인다.
- [ ] 와이파이를 끄면 "인터넷 연결이 필요해요" 배너가 뜨고 수정이 막힌다.
- [ ] "체험하기"를 눌러 샘플 집이 열리고, 검색·깜빡임 안내까지 동작한다. "종료"를 누르면 빈 상태로 돌아간다.
- [ ] 폰 Chrome에서 주소를 열고 "홈 화면에 추가"로 설치한 뒤, 아이콘을 눌러 주소창 없이 열린다.
- [ ] F12 → Application 탭에서 Manifest·Service Worker가 정상으로 인식된다(로컬 `npm run preview` 기준).
- [ ] 집 화면 → "가족 공유"에서 코드를 만들고, 다른 브라우저(시크릿 창)에서 그 코드로 참여하면 같은 집이 보인다. 엉뚱한 코드는 "존재하지 않는 코드예요."가 뜬다.

## 가족 공유 확인하기

집 화면 상단바의 "가족 공유"(👪)에서 코드를 만들고, 다른 기기(또는 다른 브라우저의 시크릿 창 — 같은 브라우저의 다른 탭은 로그인 세션을 공유해서 "다른 사람"이 아니라 "같은 나"가 됩니다)에서 메인 화면의 "가족 코드로 참여"로 그 코드를 입력하면 같은 집이 보여야 합니다.

**접근이 막히는지 확인하는 방법** (폰 2대 또는 시크릿 창 2개)
1. 기기 A에서 집을 만들고 가족 공유 코드를 발급합니다.
2. 기기 B(다른 브라우저 프로필/시크릿 창)에서 그 코드로 참여합니다. 집 안 내용이 보이고 편집도 되는지 확인합니다.
3. 기기 B에서 **엉뚱한 코드**(아무 8자리)를 입력하면 "존재하지 않는 코드예요."가 떠야 합니다.
4. 기기 A(소유자)에서 "가족 공유 → 공유 중지"를 누릅니다. 기기 B에서 그 집 화면을 새로고침(또는 메인으로 나갔다 다시 들어가기)하면 목록에서 사라져야 합니다(더 이상 접근 권한이 없어서).
5. 개발자 도구(F12) → Network 탭에서 Realtime Database 요청이 실패(permission_denied)하는지도 확인할 수 있습니다.

**동시 수정이 서로 안 덮어쓰는지 확인하는 방법**
1. 기기 A와 B 둘 다 같은 집의 같은 층(도면) 화면을 열어둡니다.
2. 기기 A에서 방 하나를 그리고, 거의 동시에 기기 B에서 다른 이름으로 가구를 하나 추가합니다.
3. 두 변경 모두 두 기기 화면에 다 남아 있어야 합니다(둘 다 새로 고침 없이 실시간으로 보임). Realtime Database는 각 항목이 서로 다른 id를 가진 별도 경로에 저장되기 때문에, 같은 화면을 동시에 고쳐도 서로 다른 항목이라면 덮어쓰지 않습니다. (같은 항목을 두 기기에서 동시에 고치면 나중에 도착한 쪽이 이기는 것은 정상입니다 — 이건 이번 범위에서 다루지 않는 "동시에 같은 값 수정" 충돌 해결이 아니라, "서로 다른 항목이 사라지지 않는지"를 확인하는 것입니다.)

## 현재 상태

Firebase(Realtime Database)에 연결되어 실제로 저장되고, 가족 공유 코드로 집을 공유할 수 있습니다. `.env`를 설정하지 않으면 로컬(메모리) 저장으로 자동 대체되며, 이 경우 새로고침하면 데이터가 초기화됩니다. 체험하기 모드는 항상 별도의 로컬 저장소를 씁니다.
